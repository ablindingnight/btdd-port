# M2: playable window (2026-11-23/24)

## Result
- **Picture identical to FCEUX**: the NES palette index of every pixel matches FCEUX at 22 frames spread over
  the 2P TAS (old-PPU model) and 17 frames over the 1P TAS (new-PPU model): title, attract mode, every level,
  bosses, mid-frame scroll splits (status bar), sprites with priority, the 8-per-line limit and flicker.
  Checked with `btdd_shot` vs `tools/fceux/screendump.lua`, compared by `tools/shotdiff.py`.
- `btdd_play` runs the game at 60.0988 Hz paced by the audio device (exactly 120 frames per 1,998 ms
  measured), with sound from the M3 APU.
- Input verified end to end: keyboard (Enter took the game from the title screen to Level 1) and gamepad
  (`btdd_play --selftest-gamepad`: an SDL virtual pad's Start/A/B/Down/Right appear in the game's own input
  byte `$30`).
- Emulation untouched: the 2P (old PPU) and 1P (new PPU) RAM gates and the 2P apudiff stay identical. The
  only edits to the PPU are a display hook (`Ppu.line_done`, 2 lines each in `ppu.c` and `ppu_new.c`,
  marked "M2 hook").

## How the picture is made (`src/platform/screen.c`)
- The PPU calls `line_done(y)` when line y is final for its model.
- Old model (FCEUX old PPU, default): the PPU has already drawn the line's background lazily, tile by tile,
  exactly as FCEUX does (fine scroll, mid-line register changes, left-8 masking), and `Ppu.line_sprites`
  holds the sprites fetched for that line. The screen composites them like FCEUX: lowest OAM index wins,
  behind-background sprites show only over background color 0, left 8 pixels hidden by PPUMASK bit 2,
  greyscale.
- New model: its dot loop already produced final pixels; they are copied.
- Colors: a palette generated by simulating the NES composite signal and decoding NTSC (our own; FCEUX's
  palette data is not used). Emphasis bits are kept per line and applied in the palette (8 variants).
- `png.c` writes PNGs without a compression library.

## btdd_play
```
btdd_play [ROM] [--movie X.fm2] [--frames N] [--ppu old|new] [--scale S] [--fullscreen] [--no-audio]
```
- Settings: `btdd.cfg` next to the exe if present, otherwise `%APPDATA%\btdd\btdd.cfg` (created with
  defaults on first run): `rom`, `scale`, `aspect` (0 = square pixels with integer scaling, 1 = 8:7 pixels,
  i.e. a 4:3 picture), `fullscreen`, `ppu`, `volume`, and `p1_*` / `p2_*` key names (SDL key names).
- Default keys: player 1 arrows, X = A, Z = B, Right Shift = Select, Enter = Start; player 2 W/A/S/D,
  H = A, G = B, T = Select, Y = Start. Gamepads: first two pads are players 1 and 2; right face button = A,
  bottom face button = B, Back = Select, Start, d-pad or left stick.
- Hotkeys: Esc quit, P pause, F11 or Alt+Enter fullscreen, F2 square pixels / 4:3, F12 screenshot (saved in
  the settings folder).
- Pacing: a frame is emulated whenever fewer than 3 frames of sound are queued (48 kHz mono float
  `SDL_AudioStream`); without an audio device, a 60.0988 Hz timer.
- The APU is attached the same way as in `btdd_apu_check` (per-instruction `Cpu.exec_hook` + `Nes.apu_hook`),
  so no runtime file changed. When the coverage branch is merged, these can become a dedicated tick in
  `cpu.c` and an `Apu` owned by `nes.c` (see docs/M3_APU.md).

## Known gaps
- Startup takes about 5 s and shutdown a few seconds on this machine tonight (window/renderer creation;
  the GPU is busy with the local model). Steady state is unaffected.
- `--selftest-gamepad` sets SDL's "background joystick events" hint so it works unfocused; normal play
  ignores pads while the window is not focused (SDL default).
- No save states, rebinding UI, or reset key yet (M8). Overscan is shown in full (no cropping).
- The 4:3 mode scales with nearest-neighbour, so columns are slightly uneven; a sharp-bilinear shader is a
  later quality item.
